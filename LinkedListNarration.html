0 · Why Linked Lists?5 min

🌱 Start here — A train made of connected cars

Say this first: Imagine three train cars. Each car carries a number and has a connector to the next car. To add a car at the front, we attach it to the old first car. That is the basic idea of a linked list.

10 → 20 → 30 → END

Introduce the vocabulary: A node is one car. data is its number. next is its connector. null means there is no next car.

Teaching move: Before discussing performance, draw three boxes. Ask students to point at the first car, then at the car after it. Only then say “node” and “reference”.

🎙️ What to say

Start with a simple situation: imagine an array with 100 values. We want to insert a new value at position 2. What must happen to the existing values? They shift. In a linked list, nodes are not required to sit next to each other in memory. Each node contains data and a reference to the next node. Inserting can therefore change references instead of shifting the elements.

🙋 Ask students — pause for answers

  • Does a linked list have a fixed capacity like an array?

    Instructor answer: No. A linked list grows or shrinks as nodes are allocated or removed; it is limited by available memory. A Java array has a fixed length once created.

  • Can we instantly jump to element number 50 in a singly linked list?

    Instructor answer: No. You must follow next links from the head until reaching that position: O(n) time.

🧠 Explanation / board walkthrough

Use this diagram throughout: first → [10 | next] → [20 | next] → [30 | null]. A node carries data and a link; null marks the end.

1 · References8 min

🌱 Start here — Two labels, one box

Say this first: Suppose I put one notebook on a desk and give it two labels, X and Y. There are not two notebooks—both labels identify the same one. Java reference variables work similarly: x and y can refer to one object.

x ─┐
   ├──→ [ Node: data = 7 ]
y ─┘

Introduce the vocabulary: A primitive such as int stores a value; a variable of a class type such as Node stores a reference to an object. null means no object is referenced.

Teaching move: First draw int a=5, int b=a: two separate values. Then draw Node x=new Node(7), Node y=x: two reference labels pointing to one box. Have students predict x.data after changing y.data.

🎙️ What to say

Before writing a list, we need to understand references. Look at int a = 5 and int b = a. Changing b does not change a. Now look at Node y = x: that copies a reference, not a separate Node object. Both variables point to the same object. When y.data becomes 99, x.data also reads 99.

🙋 Ask students — pause for answers

  • Before running: what prints for a?

    Instructor answer: The value assigned to a by the program. Trace the actual assignment and distinguish a primitive value from a node reference; use the displayed program output to confirm.

  • If y.data = 99, what does x.data print, and why?

    Instructor answer: 99, if x and y refer to the same Node object. Updating its data through y is visible through x.

  • Does Node z = null create a Node object?

    Instructor answer: No. It declares a reference variable containing null; no Node object is allocated.

🧠 Explanation / board walkthrough

Trace new Node(7): an object is created, x refers to it, then y receives the same reference. Node next is a reference field that can point to another Node. No import is needed for this example.

ReferencesDemo.java
public class ReferencesDemo {
    public static void main(String[] args) {
        // --- primitives: copied by VALUE ---
        int a = 5;
        int b = a;
        b = 10;
        System.out.println("a = " + a);   // 5

        // --- objects: copied by REFERENCE ---
        Node x = new Node(7);
        Node y = x;
        y.data = 99;
        System.out.println("x.data = " + x.data);   // 99

        Node z = null;
        if (z == null) System.out.println("z points to nothing");
    }
}

class Node {
    int data;
    Node next;
    Node(int d) { data = d; }
}
Expected output a = 5 x.data = 99 z points to nothing

2 · Simple Linked List12 min

🌱 Start here — Build the first chain, one node at a time

Say this first: We have an empty train track. Our class keeps a variable called first, which tells us where the chain begins. Let us add 22. Now let us put 44 in front of 22. The trick is to connect 44 to 22 BEFORE changing first to 44.

Empty:  first → null
Add 22: first → [22] → null
Add 44: first → [44] → [22] → null

Introduce the vocabulary: Link represents one node. LinkList manages the chain. first is a reference to the first node. insertFirst adds a node at the beginning.

Teaching move: Trace the two crucial lines slowly: newLink.next = first; then first = newLink;. Ask students to draw the picture after each line, not merely after the method finishes.

🎙️ What to say

Now we build a list ourselves. A Link object stores the integer data and a Link next. The LinkList class stores first, a reference to the first node. When first == null, the list is empty. To insert a new first node, we connect its next to the old first, then update first. Read those two assignment lines in order.

🙋 Ask students — pause for answers

  • After insertFirst(22), what does first reference?

    Instructor answer: first refers to the newly created node containing 22.

  • After insertFirst(44) and insertFirst(66), what is the order?

    Instructor answer: 66 → 44 → 22 → null, because each new item is placed at the head.

  • What breaks if we reverse the two insertFirst assignment statements?

    Instructor answer: If first = newNode happens before newNode.next = first, newNode.next points back to newNode itself. The prior chain is lost from the head and traversal may loop forever.

  • Why must traversal update current = current.next?

    Instructor answer: It moves the reference to the next node. Without that statement, the loop stays on the same node forever (unless it breaks for another reason).

🧠 Explanation / board walkthrough

Explain the roles of Link (node), LinkList (manager), and SimpleLinkedListApp (driver). Emphasize that import java.util.NoSuchElementException is required for the explicit empty-list exception. deleteFirst returns the removed node; because the caller still holds removed, it is not immediately unreachable or eligible for collection. In traversal, current = current.next prevents an infinite loop.

SimpleLinkedListApp.java
import java.util.NoSuchElementException;

class Link {
    public int data;
    public Link next;
    public Link(int d) { data = d; next = null; }
    public void display() { System.out.print(data + " "); }
}

class LinkList {
    private Link first;
    public LinkList() { first = null; }
    public boolean isEmpty() { return first == null; }

    public void insertFirst(int d) {
        Link newLink = new Link(d);
        newLink.next = first;
        first = newLink;
    }

    public Link deleteFirst() {
        if (isEmpty()) throw new NoSuchElementException("List is empty");
        Link temp = first;
        first = first.next;
        return temp;
    }

    public void displayList() {
        System.out.print("List (first --> last): ");
        Link current = first;
        while (current != null) {
            current.display();
            current = current.next;
        }
        System.out.println();
    }
}

public class SimpleLinkedListApp {
    public static void main(String[] args) {
        LinkList list = new LinkList();
        list.insertFirst(22);
        list.insertFirst(44);
        list.insertFirst(66);
        list.displayList();
        Link removed = list.deleteFirst();
        System.out.println("Deleted: " + removed.data);
        list.displayList();
    }
}
Expected output List (first --> last): 66 44 22 Deleted: 66 List (first --> last): 44 22

3 · Find and Delete12 min

🌱 Start here — Find a person in a line, then remove them

Say this first: Imagine people holding hands in a line. To find student 44, start at the front and ask each person for their number. To remove 44, student 66 must link directly to student 22. We do not pick up or physically move the other students.

Before: [66] → [44] → [22] → null
After:  [66] ───────→ [22] → null

Introduce the vocabulary: current is the node we are examining. previous is the node immediately before it. previous.next = current.next makes the chain skip the node being removed.

Teaching move: Use your finger as current and a second finger as previous. Move both along the drawing; pause when current reaches 44. Explain why deleting the first node is different: no previous node exists.

🎙️ What to say

Suppose we have 66 → 44 → 22. How can we find 44? We start with current = first and move current to current.next until data matches. To delete 44, we also need previous, because previous.next must skip current and point to current.next. Nobody moves in memory; only the reference changes.

🙋 Ask students — pause for answers

  • Which variables do we need for deleting a middle node?

    Instructor answer: Usually current and previous: current identifies the node to remove, and previous.next can be redirected to current.next.

  • What special case appears when deleting the first node?

    Instructor answer: There is no previous node. Instead set first = first.next; if that was the sole node, first becomes null.

  • What should find return if the value is absent?

    Instructor answer: Typically null for a method returning a Node (or false/-1 for other API designs). Match the return type used by this implementation.

🧠 Explanation / board walkthrough

Walk current and previous on the board. When current.data == key, if previous == null, use first = first.next; otherwise use previous.next = current.next. Never dereference current before checking that current != null.

FindDeleteApp.java
class Link {
    public int data;
    public Link next;
    public Link(int d) { data = d; }
}

class LinkList {
    private Link first;

    public void insertFirst(int d) {
        Link newLink = new Link(d);
        newLink.next = first;
        first = newLink;
    }

    public Link find(int key) {
        Link current = first;
        while (current != null) {
            if (current.data == key) return current;
            current = current.next;
        }
        return null;
    }

    public Link delete(int key) {
        Link current = first;
        Link previous = null;
        while (current != null && current.data != key) {
            previous = current;
            current = current.next;
        }
        if (current == null) return null;
        if (previous == null)
            first = first.next;
        else
            previous.next = current.next;
        return current;
    }

    public void displayList() {
        Link current = first;
        while (current != null) {
            System.out.print(current.data + " ");
            current = current.next;
        }
        System.out.println();
    }
}

public class FindDeleteApp {
    public static void main(String[] args) {
        LinkList list = new LinkList();
        list.insertFirst(22);
        list.insertFirst(44);
        list.insertFirst(66);
        list.displayList();
        Link found = list.find(44);
        System.out.println("Found: " + (found == null ? "none" : found.data));
        Link removed = list.delete(44);
        System.out.println("Deleted: " + (removed == null ? "none" : removed.data));
        list.displayList();
    }
}
Expected output 66 44 22 Found: 44 Deleted: 44 66 22

4 · Double-Ended Linked List9 min

🌱 Start here — Remember the first and last cars

Say this first: If our train knows only its first car, we have to walk through the train to find the end. What if we also kept a label on the last car? We could attach a new car directly at the end.

first → [10] → [20] → [30] ← last
                   [30].next → null

Introduce the vocabulary: A double-ended list remembers first and last. This does not mean nodes point backward. The nodes are still connected by next only.

Teaching move: Compare adding 40 with and without last. Explain that removing the last node still requires finding the one before it in a singly linked list.

🎙️ What to say

Until now, we have only first. To insert at the end, we would otherwise have to visit every node. A double-ended singly linked list stores first and last. Now we can insert at the beginning or end in constant time. This does NOT make the list doubly linked: each node still has only next.

🙋 Ask students — pause for answers

  • When inserting the very first item, which references must be updated?

    Instructor answer: Both first and last must refer to the new node; its next is null.

  • Is deleteLast O(1) merely because we have last? Why not?

    Instructor answer: No. In a singly linked list, last does not link backward. To remove it and update last, you must find its predecessor by traversing from first: O(n).

🧠 Explanation / board walkthrough

For an empty list, first and last must both refer to the new node. For a nonempty list, last.next = newLink, then last = newLink. Deleting the tail remains O(n) since the nodes do not know their predecessors.

DoubleEndedApp.java
class Link {
    int data;
    Link next;
    Link(int d) { data = d; }
}
class FirstLastList {
    private Link first;
    private Link last;
    public boolean isEmpty() { return first == null; }
    public void insertFirst(int d) {
        Link newLink = new Link(d);
        if (isEmpty()) last = newLink;
        newLink.next = first;
        first = newLink;
    }
    public void insertLast(int d) {
        Link newLink = new Link(d);
        if (isEmpty()) first = newLink;
        else last.next = newLink;
        last = newLink;
    }
    public Link deleteFirst() {
        if (isEmpty()) return null;
        Link temp = first;
        first = first.next;
        if (first == null) last = null;
        return temp;
    }
    public void displayList() {
        Link current = first;
        while (current != null) {
            System.out.print(current.data + " ");
            current = current.next;
        }
        System.out.println();
    }
}
public class DoubleEndedApp {
    public static void main(String[] args) {
        FirstLastList list = new FirstLastList();
        list.insertFirst(22);
        list.insertLast(44);
        list.insertLast(66);
        list.displayList();
        list.deleteFirst();
        list.displayList();
    }
}
Expected output 22 44 66 44 66

5 · Sorted Linked List10 min

🌱 Start here — Keep the line in number order

Say this first: Think of a classroom line sorted by student ID. A new student numbered 40 arrives. They do not go first or last; they go between 30 and 50. A sorted linked list finds the right neighbors and inserts the new node between them.

Before: [20] → [30] → [50] → null
After:  [20] → [30] → [40] → [50] → null

Introduce the vocabulary: Sorted means values remain in order. We search using current and previous; then change a couple of links to insert at that location.

Teaching move: Ask students where 10, 35, and 99 belong. Discuss the special case of a new smallest value before showing the insertion loop.

🎙️ What to say

A sorted list stays ordered. When inserting 40 into 20 → 30 → 50, we cannot simply attach it at the front. We search for the insertion position while keeping previous and current. We place 40 between 30 and 50. This traversal makes insertion O(n), but removing the smallest value from the front is O(1).

🙋 Ask students — pause for answers

  • Where does 35 belong in 20 → 30 → 50?

    Instructor answer: Between 30 and 50: 20 → 30 → 35 → 50.

  • What changes if the list is empty?

    Instructor answer: Set first to the new node; there is no predecessor to link.

  • Why is remove-min fast?

    Instructor answer: The smallest element is at first in an ascending sorted list, so removing it is a head update: O(1).

🧠 Explanation / board walkthrough

The loop searches until the first node whose data is at least the new key. The inserted node points to current, while previous.next points to it, or first is updated for a new minimum.

SortedListApp.java
class Link {
    int data;
    Link next;
    Link(int d) { data = d; }
}
class SortedList {
    private Link first;
    public void insert(int key) {
        Link newLink = new Link(key);
        Link previous = null;
        Link current = first;
        while (current != null && current.data < key) {
            previous = current;
            current = current.next;
        }
        if (previous == null) first = newLink;
        else previous.next = newLink;
        newLink.next = current;
    }
    public Link remove() {
        if (first == null) return null;
        Link temp = first;
        first = first.next;
        return temp;
    }
    public void displayList() {
        Link current = first;
        while (current != null) {
            System.out.print(current.data + " ");
            current = current.next;
        }
        System.out.println();
    }
}
public class SortedListApp {
    public static void main(String[] args) {
        SortedList list = new SortedList();
        list.insert(50);
        list.insert(20);
        list.insert(40);
        list.insert(30);
        list.displayList();
        System.out.println("Removed minimum: " + list.remove().data);
        list.displayList();
    }
}
Expected output 20 30 40 50 Removed minimum: 20 30 40 50

6 · Efficiency6 min

🌱 Start here — Count the steps, not the seconds

Say this first: How much work do we do? If I put a new car at the beginning, I change two arrows even for a very long train. But if I need the car at position 50, I have to follow the chain through 49 earlier cars.

Insert at front: fixed number of steps → O(1)
Find by position: steps grow with list length → O(n)

Introduce the vocabulary: O(1) means the number of steps does not grow with the length of the list. O(n) means the work can grow approximately with the number of nodes.

Teaching move: Draw a list of 3 nodes, then 10 nodes. Have students compare work to insertFirst versus work to find the last node. Emphasize that O(1) does not mean zero work.

🎙️ What to say

Now let's compare operations rather than memorizing slogans. Arrays access any known index in O(1), but insertion at the beginning costs O(n) because values shift. Singly linked lists can insert at the front in O(1), but finding the kth node is O(n). Keeping last speeds insertLast but does not speed deleteLast in a singly linked list. Sorted insertion requires finding the right position.

🙋 Ask students — pause for answers

  • Which is preferable for frequent indexed lookups?

    Instructor answer: An array or ArrayList, because indexed access is O(1), whereas a linked list must traverse: O(n).

  • Which implementation allows O(1) insertLast?

    Instructor answer: A double-ended singly linked list with a last (tail) pointer can append in O(1), assuming no traversal is needed.

  • Does searching a linked list become O(1) just because insertion is O(1)?

    Instructor answer: No. Finding a value still requires traversing up to n nodes: O(n).

🧠 Explanation / board walkthrough

Distinguish searching for a position, which may be O(n), from rewiring references after a node has been located, which is O(1). No additional Java demo is necessary: use the previous four programs.

7 · Doubly Linked List12 min

🌱 Start here — A two-way street

Say this first: Until now, our arrows only point forward. Think of a one-way street. If each node also knows the node behind it, we can travel in either direction. That is a doubly linked list.

null ← [10] ⇄ [20] ⇄ [30] → null

Introduce the vocabulary: Each node has two links: next (forward) and previous (backward). Updating one direction alone is not enough; both directions must remain correct.

Teaching move: Start with two boxes and draw both arrows. Insert a third box between them. Have students identify the four arrow changes before displaying the Java code.

🎙️ What to say

A singly linked node knows who comes next but not who comes before. What if a node also stored previous? Now we can traverse both directions and delete the last node directly when we maintain last. But each insertion and deletion must update two directions correctly.

🙋 Ask students — pause for answers

  • What must first.previous be?

    Instructor answer: null. The head node has no predecessor.

  • What must last.next be?

    Instructor answer: null. The tail node has no successor.

  • When inserting after 22, what references must be repaired?

    Instructor answer: Connect the new node to both neighbors: newNode.previous = node22; newNode.next = oldNext; node22.next = newNode; and if oldNext exists, oldNext.previous = newNode. Otherwise update last.

🧠 Explanation / board walkthrough

Use 44 ⇄ 22 ⇄ 66. Inserting 33 after 22 requires connections between 22, 33, and 66 in both directions. Show forward and backward traversal, then deleteLast. This example is a self-contained demonstration of the operations in your lecture.

DoublyLinkedApp.java
class Node {
    int data;
    Node next;
    Node previous;
    Node(int d) { data = d; }
}
class DoublyLinkedList {
    private Node first;
    private Node last;
    public void insertFirst(int d) {
        Node n = new Node(d);
        n.next = first;
        if (first == null) last = n;
        else first.previous = n;
        first = n;
    }
    public void insertLast(int d) {
        Node n = new Node(d);
        n.previous = last;
        if (last == null) first = n;
        else last.next = n;
        last = n;
    }
    public boolean insertAfter(int key, int d) {
        Node current = first;
        while (current != null && current.data != key) current = current.next;
        if (current == null) return false;
        Node n = new Node(d);
        n.previous = current;
        n.next = current.next;
        if (current.next == null) last = n;
        else current.next.previous = n;
        current.next = n;
        return true;
    }
    public Node deleteFirst() {
        if (first == null) return null;
        Node old = first;
        first = first.next;
        if (first == null) last = null;
        else first.previous = null;
        return old;
    }
    public Node deleteLast() {
        if (last == null) return null;
        Node old = last;
        last = last.previous;
        if (last == null) first = null;
        else last.next = null;
        return old;
    }
    public void displayForward() {
        System.out.print("Forward: ");
        for (Node n = first; n != null; n = n.next) System.out.print(n.data + " ");
        System.out.println();
    }
    public void displayBackward() {
        System.out.print("Backward: ");
        for (Node n = last; n != null; n = n.previous) System.out.print(n.data + " ");
        System.out.println();
    }
}
public class DoublyLinkedApp {
    public static void main(String[] args) {
        DoublyLinkedList list = new DoublyLinkedList();
        list.insertFirst(22);
        list.insertFirst(44);
        list.insertLast(66);
        list.insertAfter(22, 33);
        list.displayForward();
        list.displayBackward();
        list.deleteLast();
        list.deleteFirst();
        list.displayForward();
    }
}
Expected output Forward: 44 22 33 66 Backward: 66 33 22 44 Forward: 22 33

8a · Hand-Written Iterator12 min

🌱 Start here — A bookmark that remembers your place

Say this first: When reading a book, you can move a bookmark page by page instead of reopening at page one. An iterator plays a similar role: it remembers where we are in the linked list.

list: [10] → [20] → [30]
                  ↑
             iterator.current

Introduce the vocabulary: The list stores the nodes. The iterator remembers a position and provides operations for moving through the list. An iterator that can delete may also need to remember the previous node.

Teaching move: Trace current and previous in different colors. Ask students which node the iterator points at after one move and after two moves.

🎙️ What to say

An iterator is a bookmark: instead of forcing outside code to access first and next, the iterator remembers a current position. We can reset the bookmark, move it forward, insert after it, or delete the current node. Our own iterator must remember previous as well because deletion needs to bypass the current node.

🙋 Ask students — pause for answers

  • What is the difference between a list and an iterator?

    Instructor answer: The list stores the nodes; an iterator stores traversal state (such as current and previous) and defines how to visit or modify nodes.

  • Why does deleteCurrent need previous?

    Instructor answer: For deletion in a singly linked list, previous is needed to bypass the node: previous.next = current.next. Head deletion is a special case.

  • Can two iterators point to different nodes in the same list?

    Instructor answer: Yes. Each iterator can maintain independent position references while sharing the same underlying list. Structural changes may affect them.

🧠 Explanation / board walkthrough

The original lecture uses reset, atEnd, nextLink, getCurrent, insertAfter, and deleteCurrent. Follow current and previous after each call. Guard empty or invalid iterator positions to avoid dereferencing null.

IteratorApp.java
class Link {
    int data;
    Link next;
    Link(int d) { data = d; }
}
class LinkList {
    private Link first;
    public Link getFirst() { return first; }
    public void setFirst(Link f) { first = f; }
    public boolean isEmpty() { return first == null; }
    public ListIterator getIterator() { return new ListIterator(this); }
    public void displayList() {
        for (Link p = first; p != null; p = p.next) System.out.print(p.data + " ");
        System.out.println();
    }
}
class ListIterator {
    private Link current;
    private Link previous;
    private final LinkList ourList;
    public ListIterator(LinkList list) { ourList = list; reset(); }
    public void reset() { current = ourList.getFirst(); previous = null; }
    public boolean atEnd() { return current == null || current.next == null; }
    public void nextLink() {
        if (current == null) throw new IllegalStateException("No current node");
        previous = current;
        current = current.next;
    }
    public Link getCurrent() { return current; }
    public void insertAfter(int d) {
        Link n = new Link(d);
        if (ourList.isEmpty()) {
            ourList.setFirst(n);
            current = n;
            previous = null;
        } else {
            if (current == null) throw new IllegalStateException("No current node");
            n.next = current.next;
            current.next = n;
            previous = current;
            current = n;
        }
    }
    public int deleteCurrent() {
        if (current == null) throw new IllegalStateException("No current node");
        int value = current.data;
        if (previous == null) ourList.setFirst(current.next);
        else previous.next = current.next;
        current = (previous == null) ? ourList.getFirst() : previous.next;
        return value;
    }
}
public class IteratorApp {
    public static void main(String[] args) {
        LinkList list = new LinkList();
        ListIterator it = list.getIterator();
        it.insertAfter(20);
        it.insertAfter(40);
        it.insertAfter(80);
        it.reset();
        it.nextLink();
        it.insertAfter(60);
        list.displayList();
        it.reset();
        while (true) {
            System.out.print("[" + it.getCurrent().data + "] ");
            if (it.atEnd()) break;
            it.nextLink();
        }
        System.out.println();
        it.reset();
        it.nextLink();
        System.out.println("Deleted " + it.deleteCurrent());
        list.displayList();
    }
}
Expected output 20 40 60 80 [20] [40] [60] [80] Deleted 40 20 60 80

8b · Java Iterator and for-each10 min

🌱 Start here — Java can move the bookmark for us

Say this first: We just built our own way of walking through a list. Java also gives us standard tools. The Iterator interface uses hasNext() to ask whether another item exists and next() to get it. The for-each loop uses that idea for us.

while (it.hasNext()) { print(it.next()); }

for (int number : list) { print(number); }

Introduce the vocabulary: Iterator is a Java interface. Iterable means a class knows how to provide an iterator. The enhanced for loop visits items one by one.

Teaching move: Run the explicit iterator loop first. Ask the students to compare its output with for-each; both should visit the same values in the same order.

🎙️ What to say

Java already defines Iterator with hasNext and next. If our list implements Iterable<Integer> and supplies iterator(), the enhanced for loop works automatically. Students should recognize that for-each repeatedly asks hasNext() then next(). We first demonstrate the explicit loop, and then compare with the shorter for-each syntax.

🙋 Ask students — pause for answers

  • What is the role of implements Iterable<Integer>?

    Instructor answer: It promises an iterator() method returning an Iterator<Integer>, allowing the list to be used in enhanced for loops.

  • What happens if next is called after hasNext becomes false?

    Instructor answer: The standard Iterator contract requires throwing NoSuchElementException if next() is called when nothing remains.

  • Does for-each avoid traversal costs?

    Instructor answer: No. A for-each loop uses an iterator behind the scenes; visiting all n nodes is still O(n).

🧠 Explanation / board walkthrough

Explain import java.util.Iterator and NoSuchElementException. The iterator starts at first, next returns the current data and advances the reference. The enhanced for loop uses exactly this iterator machinery behind the scenes.

ForEachApp.java
import java.util.Iterator;
import java.util.NoSuchElementException;

class Link {
    public int data;
    public Link next;
    public Link(int d) { data = d; }
}
class LinkList implements Iterable<Integer> {
    private Link first;
    public void insertFirst(int d) {
        Link newLink = new Link(d);
        newLink.next = first;
        first = newLink;
    }
    @Override
    public Iterator<Integer> iterator() {
        return new Iterator<Integer>() {
            private Link current = first;
            @Override
            public boolean hasNext() { return current != null; }
            @Override
            public Integer next() {
                if (current == null) throw new NoSuchElementException();
                int value = current.data;
                current = current.next;
                return value;
            }
        };
    }
}
public class ForEachApp {
    public static void main(String[] args) {
        LinkList list = new LinkList();
        list.insertFirst(30);
        list.insertFirst(20);
        list.insertFirst(10);
        Iterator<Integer> it = list.iterator();
        while (it.hasNext()) {
            System.out.print(it.next() + " ");
        }
        System.out.println();
        int sum = 0;
        for (int value : list) {
            sum += value;
        }
        System.out.println("Sum: " + sum);
    }
}
Expected output 10 20 30 Sum: 60

9–10 · Playground and Quick Check8 min

🌱 Start here — Students build and explain the chain

Say this first: Now we test whether we understand the arrows. Start empty, add 22, add 44 at the beginning, add 66 at the end, and delete 44. After every operation, draw the chain before checking the visualizer.

empty → [22] → [44,22] → [44,22,66] → [22,66]

Introduce the vocabulary: The goal is to explain why the references change, not just remember method names. If you can draw before and after, the code becomes easier to read.

Teaching move: Give students 30 seconds to draw each step. Then ask them to explain the exact Java assignment responsible for the change.

🎙️ What to say

We finish by predicting changes before pressing a control. Start with an empty list. Insert 22, then 44 at the front, then 66 at the end. Ask students to sketch the chain before showing the visualizer. Find 44, delete 44, and compare the before/after arrows. Toggle doubly linked and explain the backward connections. Finally, have students explain one line of code in their own words.

🙋 Ask students — pause for answers

  • Why does insertFirst not require a loop?

    Instructor answer: It changes only a fixed number of references: newNode.next = first; first = newNode. No nodes need to be visited.

  • What happens if delete(999) is called?

    Instructor answer: If 999 is absent, no node should be deleted. The method should indicate failure according to its API (for example, false or null).

  • What changes in a doubly linked node?

    Instructor answer: Each node has both next and previous references, enabling traversal in both directions and easier local relinking.

  • Which data structure is better for instant indexed access?

    Instructor answer: An array or ArrayList: O(1) indexed access.
