The problem with arrays

Definition
  • An array has a fixed size chosen when it is created.
  • Inserting or deleting in the middle means shifting every item after it → slow (O(n)).
  • A linked list grows one item at a time and inserts/deletes without shifting.
Picture it 🎢 An array is a row of theater seats: to add a person in the middle, everyone after them must stand up and move one seat over. A linked list is a treasure hunt: each clue (a node) holds a prize (data) and the location of the next clue (next). To add a clue in the middle, you only rewrite one location — nobody else moves.
A linked list of three nodes. first points to the first node; the last node's next is null.

1 · References

Definition
  • A reference is a variable that holds the address of an object, not the object itself.
  • Node y = x; copies the address → x and y now point to the same object.
  • null means "points to nothing".
  • Every linked-list node is reached through a reference called next.
Picture it 🏠 Imagine the object is a house and the reference is a sticky note with the house's address. Copying the note (y = x) gives you two notes for the same house. Repainting the house through either note (y.data = 99) changes the one house. A blank note is null.
Left: primitives are copied by value. Right: references are copied by address — same object.

2 · Simple Linked List

Definition
  • A node (we call the class Link) holds data + a reference next to the following node.
  • The list class stores only one reference: first.
  • The list is empty when first == null.
  • To visit every node: start at first, follow next until you hit null → this is traversal.

Tiny steps first

Step 1 — a node class 
class Link {
    int data;
    Link next;
}
Step 2 — chain two nodes by hand 
Link a = new Link();  a.data = 10;
Link b = new Link();  b.data = 20;
a.next = b;        // 10 → 20
b.next = null;     // end
insertFirst: (1) the new node points to the old first, (2) first points to the new node. Order matters!
Common mistake Doing first = newLink; before newLink.next = first; loses the whole old list — the new node ends up pointing to itself. Always connect the new node first, then move first.

3 · Inserting and Deleting Nodes

Definition
  • find(key): walk from first until current.data == key (or null = not found).
  • delete(key): you need two references while walking: current (the one to remove) and previous (the one before it).
  • Deleting = making previous.next skip over current. The skipped node is garbage-collected.
  • Special case: deleting the first node → just move first forward.
Picture it 🚂 Removing a train car: the car before it (previous) must couple to the car after it (current.next). You can't do that if you're only standing on the car you want to remove — so we always keep track of the car behind us.
Green arrow = the one assignment that deletes 44. Nothing else moves.

4 · Double-Ended Lists

Definition
  • A double-ended list keeps two references: first and last.
  • Benefit: insertLast() becomes O(1) — no need to walk the whole list to find the end.
  • Still a singly linked list: nodes only know next, so deleteLast() is still slow.
  • Watch the empty-list cases: the first insert must set both first and last.
Picture it 🎟️ A ticket line with a sign at the front (first) and a sign at the back (last). New people join at the back instantly — you don't walk the whole line to find the end. This is exactly how a queue is built.
Both ends are one hop away.

5 · Sorted Lists

Definition
  • A sorted list keeps its nodes in order (e.g., smallest → largest) at all times.
  • There is only one way to add: insert(key) walks forward until it finds the first node bigger than the key, then drops the new node right before it.
  • Insert is O(n) (walking), but removing the minimum (remove()) is O(1) — it's always at first.
  • Great for a priority queue: the most urgent item is always at the front.
Picture it 📚 Books on a shelf sorted by height. To add a new book, slide along until you meet the first taller book and squeeze in just before it. The shortest book is always at the far left — grabbing it takes no searching.

6 · Efficiency

Definition
  • O(1) = constant time: the number of items doesn't matter.
  • O(n) = linear time: twice the items → twice the work.
  • Linked lists win on insert/delete at the ends and never need resizing.
  • Arrays win on random access (arr[500]) because nodes aren't side-by-side in memory.

Rule of thumb Lots of inserting/removing at the ends, unknown size → linked list. Lots of jumping to position i → array. In Java, ArrayList is the array; LinkedList is the (doubly) linked list.

7 · Doubly Linked Lists

Definition
  • Each node has two references: next and previous.
  • You can traverse forward or backward.
  • deleteLast() becomes O(1) (we can reach the node before last via last.previous).
  • Cost: every insert/delete must fix twice as many references, and each node uses a little more memory.
Picture it 🚪 A hallway of rooms where every door opens both ways. In a singly linked list, doors only open forward — to go back you must return to the entrance and walk again.
Orange arrows = next, pink arrows = previous. First node's previous and last node's next are null.

8 · Iterators

Definition
  • An iterator is an object that remembers a position in the list (a "bookmark") and can move it.
  • It lets the user of the list walk through nodes without seeing first/next or knowing how the list is built.
  • Typical methods: reset(), atEnd(), nextLink(), getCurrent(), insertAfter(), deleteCurrent().
  • Java's built-in version is java.util.Iterator with hasNext() / next() — it's what powers the for-each loop.
Picture it 🔖 The list is a book; the iterator is a bookmark plus a hand that can flip one page (nextLink()), tell you the current page (getCurrent()), or tear out the current page (deleteCurrent()). Two readers can hold two bookmarks in the same book.
