Why do we need hash tables?

Goal: see the problem that hashing solves, before we learn any new words.

The problem
  • Every structure so far has to search: look at one item, then another, then another.
  • A hash table does not search. It calculates where the item is.
  • One calculation, then go straight to the right cell.
StructureFind a valueInsert a value
Unsorted arrayO(n)O(1)
Sorted arrayO(log n)O(n)
Binary search treeO(log n)O(log n)
Hash table #️⃣O(1) on averageO(1) on average
What does O(1) mean here?
  • The time does not grow when the table grows.
  • 10 items or 10 million items: about the same number of steps.
Picture it 📬
  • Imagine a wall of numbered mailboxes in an apartment building.
  • The mailboxes are the array cells. The apartment number is the index.
  • The mail carrier does not open every box. The number on the letter says which box.

Here is one. Try a search.

Nothing is free ⚖️
  • The keys are not kept in order. No sorted printing, no quick min or max.
  • The table works best when it is not too full, so we need to know roughly how much data is coming.
What we will learn
  • Part I: the vocabulary, hash functions, collisions, linear probing, deleting.
  • Part II: quadratic probing, double hashing, separate chaining, efficiency, external storage.

Hash functions

Goal: turn any key into a legal array index with one calculation.

Definition
  • A hash function takes a key and gives back an index from 0 to size - 1.
  • The simplest one: index = key % size.
  • % (modulo) is the remainder of a division.
Picture it 🕐
  • Imagine a clock. The clock face is the table, with 12 cells.
  • The number of hours is the key. The hour the hand points to is the index.
  • 15 hours after midnight the hand points to 3, because 15 % 12 = 3. The number always wraps around.

A good hash function is…
  • Fast: a few arithmetic steps, nothing more.
  • Consistent: the same key always gives the same index.
  • Spreading: it sends keys to all parts of the table, not to a few cells.
Watch out: table size 🔢
  • Make the table size a prime number (11, 23, 101, 1009).
  • With size 10, the index is just the last digit. Keys like 10, 20, 30, 40 all land in cell 0.
  • From now on our tables have 11 cells.

STEP 3Hashing a word

Definition
  • A key does not have to be a number. A String can be hashed too.
  • Every letter has a number code. We combine the codes into one number.
  • We multiply by 31 at each step so that the order of the letters matters.

Remember
  • Hash function = key in, index out.
  • key % size always gives 0 to size - 1.
  • Prime table sizes spread the keys better.

Collisions

Goal: understand the one big problem of hashing, and the two families of solutions.

Definition
  • A collision happens when two different keys hash to the same index.
  • Example with size 10: 37 % 10 = 7 and 47 % 10 = 7.
  • There are far more possible keys than cells, so collisions will happen.
Picture it 🎂
  • Imagine a classroom of 30 students and a calendar of 365 days.
  • Each student is a key. Each day is a cell. The birthday is the hash function.
  • Two students with the same birthday is a collision. It happens much more often than people expect.

Open addressing: linear probing

Goal: when a cell is taken, step forward one cell at a time until a free one appears.

Definition
  • Open addressing = on a collision, store the key in another empty cell of the same array.
  • Linear probing = try the next cell, then the next, then the next: +1, +2, +3…
  • At the end of the array, wrap around to cell 0.
  • Find follows exactly the same path. It stops at the key, or at an empty cell.
Picture it 🎬
  • Imagine a movie theater with numbered seats. Your ticket is the key, the seat number is the index.
  • Someone is in your seat, so you take the next free seat in the row.
  • Your friend looks for you by starting at your seat number and walking along the row.

Watch out: clustering 🚧
  • A cluster is a long run of filled cells next to each other.
  • Any key that hashes anywhere into the cluster must walk to its end, and then makes it one cell longer.
  • Big clusters grow faster. This is called primary clustering, and it slows everything down.
Remember
  • Linear probing: home cell, then +1, +1, +1.
  • Find stops at the key or at the first empty cell.
  • Simple, but it builds clusters.

Deleting with open addressing

Goal: remove a key without breaking the search for the keys behind it.

The problem
  • Find stops at the first empty cell.
  • If we delete a key by emptying its cell, we cut the path to every key that was probed past it.
  • Those keys are still in the table, but find can no longer reach them.

Definition: the DELETED marker
  • Instead of emptying the cell, we store a special value: DELETED.
  • Find treats it as "keep going".
  • Insert treats it as "free, you may use this cell".
Picture it 🚪
  • Imagine a hotel hallway. Each room is a cell.
  • A guest checks out. We hang a "checked out" sign on the door: that is the DELETED marker.
  • Someone searching the hallway reads the sign and keeps walking. A new guest may take the room.

Quadratic probing and double hashing

Goal: break up the clusters by taking bigger, smarter jumps.

MethodCells tried after the home cellResult
Linear probing+1, +2, +3, +4…Long clusters
Quadratic probing+1, +4, +9, +16…Jumps out of a cluster quickly
Double hashing+step, +2·step, +3·step… (step depends on the key)Each key takes its own path

Part A · Quadratic probing

Definition
  • Quadratic probing = probe number i looks i × i cells after the home cell.
  • The jumps get longer each time: 1, 4, 9, 16…
Picture it 🅿️
  • Imagine looking for parking on a busy street. Each parking space is a cell.
  • The spaces near the store are a cluster. Checking the very next space is hopeless.
  • So you drive a bit further each time: 1 space, then 4, then 9.

Watch out 🙃
  • All keys with the same home cell still follow the same jumps. That is a milder problem called secondary clustering.
  • Quadratic probing is only sure to find a free cell when the size is prime and the table is less than half full.

Part B · Double hashing

Definition
  • Double hashing = use a second hash function to choose the step size.
  • First hash: where to start. Second hash: how far to jump.
  • Two keys with the same home cell usually have different steps, so they go different ways.
  • Our second hash: step = 5 - (key % 5). It gives 1 to 5, never 0.
Picture it 🚶
  • Imagine people starting from the same front door (the home cell).
  • Each person has their own stride length (the step from the second hash).
  • Same door, different strides, so they land on different tiles (cells).
OUTPUT
Step for 26 is 4

Watch out: use a prime size 🔢
  • With a prime size, any step visits every cell before repeating.
  • With size 10 and step 5, the probes would only ever see 2 cells.
Remember
  • Linear: +1 each time. Quadratic: +i². Double hashing: +i × step.
  • All three change one line of the program: how index is calculated.
  • Double hashing is usually the best open-addressing method.

Separate chaining

Goal: let every cell hold as many keys as it needs, using a linked list.

Definition
  • Separate chaining = every cell of the array holds a linked list.
  • A key always goes into the list of its own cell. No probing.
  • A collision just makes that list one link longer.
Picture it 🧥
  • Imagine a row of coat hooks. Each hook is an array cell.
  • Each coat on a hanger is a link. Hangers hook onto each other to make a chain.
  • A full hook is not a problem. The chain simply gets longer.

Hashing efficiency

Goal: measure how full a table is, and see why a full table is a slow table.

Definition
  • Load factor = number of keys ÷ number of cells.
  • 0.25 = a quarter full. 0.5 = half full. 1.0 = completely full.
  • The higher the load factor, the more probes each operation needs.
Picture it 🅿️
  • Imagine a parking lot. The spaces are the cells, the cars are the keys.
  • Lot half empty: you park in the first place you try.
  • Lot 95% full: you drive around and around. Each loop past a taken space is a probe.

Rules of thumb
  • Open addressing: keep the load factor below about 0.5 (at most 2/3).
  • Separate chaining: a load factor around 1 is fine.
  • Hash tables are O(1) only while they are not too full.

STEP 3When the table gets too full: rehashing

Definition
  • Rehashing = create a bigger array and insert every key again.
  • We cannot just copy the cells. The index is key % size, and size changed.
  • It costs O(n), but it happens rarely.
Picture it 🏢
  • Imagine a company moving to a bigger office. Each employee is a key, each desk is a cell.
  • The new building has a different desk numbering, so nobody keeps their old desk number.
  • Everyone gets a new desk assignment: that is hashing each key again.

Hashing and external storage

Goal: use hashing to find a record in a huge disk file with only one disk read.

Definitions
  • External storage = data kept in a file on disk, because it is too big for memory.
  • A block = a chunk of the file that is read or written all at once. One block holds several records.
  • A disk access = reading or writing one block. It is thousands of times slower than working in memory.
  • So the goal changes: not "few comparisons", but "few disk accesses".
Picture it 📦
  • Imagine a warehouse of boxes. Each box is a block, each folder inside is a record.
  • Walking to the warehouse and carrying back a box is slow: that is a disk access.
  • A rule on your desk (the hash function) tells you which box to fetch. One trip, then you flip through the folders at your desk.

The steps
  • Hash the key to get a block number.
  • Read that one block from the disk.
  • Search the few records inside it, in memory. That part is fast.

Watch out: full blocks 📦
  • A block can fill up. Block 1 in our example has no room left.
  • The next record for block 1 must go to a neighbouring block (like linear probing, but block by block). That costs a second disk access.
  • So external hash files are kept only about half to two-thirds full.
Remember
  • On disk we count block reads, not comparisons.
  • Hashing usually finds a record with one block read. Nothing is faster.
  • Weakness, same as always: the records are not in order.
