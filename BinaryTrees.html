Why do we need trees?

Goal: see the problem that trees solve, before we learn any new words.

The problem
  • We already know two ways to store data: arrays and linked lists.
  • Each one is fast at one job and slow at another.
  • A binary search tree is fast at both jobs.
StructureSearch for a valueInsert a new value
Sorted arrayFast · O(log n)Slow · O(n) — must shift items
Linked listSlow · O(n) — check one by oneFast · O(1) at the front
Binary search tree 🌳Fast · O(log n)Fast · O(log n)
How fast is O(log n)?
  • Each step throws away half of the remaining data.
  • 1,000 items → about 10 steps.
  • 1,000,000 items → about 20 steps.
Picture it 🎯
  • Imagine the higher or lower guessing game (guess my number from 1 to 100).
  • Each guess is one node.
  • "Lower!" means go left. "Higher!" means go right.

Picture it 👵
  • Imagine a family tree drawn upside down.
  • The root is the great-grandmother at the top.
  • Each edge is a parent-to-child line.
  • A leaf is a family member with no kids.
  • A subtree is one branch of the family.
Watch out 🙃
  • Computer science trees grow down. The root is at the top.
  • Not every binary tree is a binary search tree. The BST needs the smaller-left / bigger-right rule.

Finding a node

Goal: search the tree for a key by making one left-or-right decision per level.

Definition
  • Find = look for the node that holds a given key.
  • Start at the root.
  • Key is smaller than the node → go left.
  • Key is bigger → go right.
  • Stop when the keys are equal (found) or when we reach null (not there).
Picture it 📖
  • Imagine looking up a word in a paper dictionary.
  • The page you open is the current node.
  • Your word comes earlier? Flip left. Later? Flip right.

Remember
  • We never look at the whole tree. Only one node per level.
  • Steps needed = the level of the node. At most the height of the tree.
  • Balanced tree → O(log n).

Inserting a node

Goal: add a new key in the right place, so the BST rule stays true.

Definition
  • Insert = add a new node to the tree.
  • Walk down exactly like find.
  • When the next spot is null, attach the new node there.
  • A new node always becomes a leaf.
Picture it 🚗
  • Imagine driving through a parking garage with signs.
  • Each sign is a node: "smaller numbers left, bigger numbers right".
  • The first empty space you reach is the null spot. Park there.

Finding the min and max values

Goal: find the smallest and the biggest key without comparing any keys at all.

Definition
  • Minimum = the smallest key. Start at the root and keep going left until there is no left child.
  • Maximum = the biggest key. Start at the root and keep going right until there is no right child.
Picture it 🛝
  • Imagine the tree is a playground with slides.
  • Always take the left slide: you land on the minimum.
  • Always take the right slide: you land on the maximum.

Traversing the tree

Goal: visit every node exactly once, in a chosen order.

Definition
  • Traverse = visit every node in the tree, one time each.
  • Visit = do something with the node. Here: print its key.
  • There are 3 classic orders. The only difference is when we visit the node itself.
Left → NODE → RightIN-order · gives sorted output
NODE → Left → RightPRE-order · node first
Left → Right → NODEPOST-order · node last
New word: recursion
  • Recursion = a method that calls itself on a smaller piece of the problem.
  • Here the smaller piece is a subtree.
  • It must have a stop rule: when the node is null, do nothing.
Picture it 🏠
  • Imagine checking every room in a house with many hallways.
  • Each room is a node. Each hallway is a subtree.
  • In-order rule: finish the whole left hallway, then this room, then the whole right hallway.

Remember
  • In-order on a BST prints the keys sorted, smallest to biggest.
  • Pre-order: the root is printed first. Useful for copying a tree.
  • Post-order: the root is printed last. Useful for deleting a whole tree.
  • Every traversal visits all n nodes → O(n).

Deleting a node

Goal: remove a node and keep the BST rule true. There are 3 cases. We go from easy to hard.

Definition
  • Delete = remove the node with a given key from the tree.
  • First find the node. Then look at how many children it has.
CaseThe node has…What we do
1no children (a leaf)Just remove it.
2one childIts child moves up and takes its place.
3two childrenReplace its key with its successor, then delete the successor.
New word: successor
  • The successor of a node is the next bigger key in the tree.
  • How to find it: go right once, then go left as far as you can.
  • It is the smallest key in the right subtree.
Picture it 🏢
  • Imagine a company org chart. Each employee is a node.
  • Case 1: an employee with no team leaves. Nothing else changes.
  • Case 2: a manager with one team member leaves. That person moves up.
  • Case 3: a manager with two teams leaves. The successor (next in line) takes the chair.

The idea of this code
  • delete(node, key) removes the key from the subtree that starts at node.
  • It returns the top of the repaired subtree.
  • The parent stores that result in its left or right link. That is how the tree gets re-connected.
OUTPUT
Start:                    20 30 35 40 45 50 60 65 70 80 
Delete 80 (leaf):         20 30 35 40 45 50 60 65 70 
Delete 60 (one child):    20 30 35 40 45 50 65 70 
Delete 30 (two children): 20 35 40 45 50 65 70 
Left child of root is now 35
Remember
  • 0 children → remove. 1 child → child moves up. 2 children → use the successor.
  • The successor never has a left child, so deleting it is always Case 1 or Case 2.
  • Cost: at most the height of the tree. Balanced tree → O(log n).

Representing trees as arrays

Goal: store a tree in a plain array with no references, using index math.

Definition
  • We can store a binary tree in an array instead of linked nodes.
  • Fill the array level by level, left to right. The root goes in index 0.
  • We find parents and children with arithmetic on the index. No left or right links.
2 * i + 1index of the LEFT child of i
2 * i + 2index of the RIGHT child of i
(i - 1) / 2index of the PARENT of i
Picture it 🎟️
  • Imagine a theater where the tree sits in rows.
  • Each seat number is an array index. Row 1 is the root.
  • You do not need arrows to find someone's children. You calculate their seat numbers.

Remember
  • Left = 2*i + 1, right = 2*i + 2, parent = (i - 1) / 2.
  • Great when the tree is full, with no holes.
  • That is exactly how a heap is stored. We will use these formulas again in the Heaps lecture.
