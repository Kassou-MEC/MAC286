Why do we need heaps?

Goal: see the problem that a heap solves, before we learn any new words.

The problem
  • A priority queue must always hand us the most important item next (here: the biggest number).
  • We met it in the Stacks & Queues lecture. With an array, one of its two jobs was always slow.
  • A heap makes both jobs fast.
Priority queue built with…InsertRemove the biggest
Unsorted arrayFast · O(1)Slow · O(n) — search for the biggest
Sorted arraySlow · O(n) — shift itemsFast · O(1)
Heap ⛰️Fast · O(log n)Fast · O(log n)
The trick
  • A heap is only partly sorted. Just enough to keep the biggest value on top.
  • Less sorting work on every insert means faster inserts.
Picture it 🏥
  • Imagine an emergency room. Each patient is a value, the urgency is the number.
  • The nurse does not line up all patients in perfect order.
  • She only needs to know who is most urgent right now: that patient is the root.

Here is one. Remove the biggest value.

Picture it 🏢
  • Imagine a company org chart. Each employee is a node, the salary is the value.
  • The rule: every boss earns at least as much as the people directly under them. That is the heap condition.
  • So the CEO (the root) earns the most.
  • Two people on the same level can earn anything. The chart is only partly ordered.
Watch out 🙃
  • A heap is not a binary search tree. There is no "smaller left, bigger right" rule.
  • You cannot search a heap quickly. It is built for one thing: giving you the biggest.
  • This "heap" has nothing to do with the heap memory where Java keeps objects. Same word, different thing.

The heap as an array

Goal: store the tree in a plain array and find parents and children with index math.

Definition
  • A heap is a complete tree, so it fits in an array with no holes.
  • We fill the array level by level, left to right. The root goes in index 0.
  • We never store references. We calculate where the parent and children are.
(i - 1) / 2index of the PARENT of i
2 * i + 1index of the LEFT child of i
2 * i + 2index of the RIGHT child of i
Picture it 🎟️
  • Imagine a theater where the tree sits in rows. Each seat number is an array index.
  • Row 1 has 1 seat, row 2 has 2, row 3 has 4. Seats are numbered straight through.
  • You find someone's children by calculating their seat numbers.

Insertion: trickle up

Goal: add a value at the bottom, then let it climb to where it belongs.

Definition
  • Insert = add a new value and keep the heap a heap.
  • Step 1: put the value in the first free cell of the array (the next spot on the bottom level).
  • Step 2: trickle up. While the value is bigger than its parent, swap them.
  • It stops when the parent is bigger, or when the value reaches the root.
Picture it 🏢
  • Imagine a new employee who starts at the bottom of the org chart.
  • The employee is the new value. Each boss above is a parent.
  • Whenever the employee earns more than the boss, they trade places. This repeats up the chart.

Remember
  • New values always start at the bottom and move up.
  • At most one swap per level. The tree has about log₂ n levels → O(log n).
  • 1,000,000 values: at most about 20 swaps.

Removal: trickle down

Goal: take out the biggest value and repair the heap from the top.

Definition
  • Remove = take out the biggest value. It is always the root, index 0.
  • Step 1: save the root.
  • Step 2: move the last value into the root. (The tree stays complete.)
  • Step 3: trickle down. While the value is smaller than a child, swap it with the larger child.
Picture it 🏢
  • Imagine the CEO (the root) retires.
  • The newest hire (the last node) is put in the CEO's chair for a moment.
  • That person keeps trading places with the higher-paid of the two people below, until everyone under them earns less.

Watch it

Watch out: always the LARGER child ⚠️
  • If we swapped 40 with the smaller child (70), then 70 would sit above 80.
  • That breaks the heap condition. The larger child is the only one fit to be the parent of the other.

Remember
  • Remove always takes the root. You cannot remove from the middle.
  • The last value goes to the top, then moves down.
  • At most one swap per level → O(log n).

Array size and expanding the heap

Goal: know the difference between how much the heap holds and how much it can hold, and grow it when it is full.

Definitions
  • Capacity = the length of the array: how many values the heap can hold. In Java: data.length.
  • Size = how many values the heap holds right now. In Java: our size field.
  • The heap lives in cells 0 to size - 1. The cells after that are unused.
  • size is also the index of the next free cell.
Picture it 🥚
  • Imagine an egg carton. The carton is the array.
  • The number of cups is the capacity. The number of eggs is the size.
  • 12 cups, 7 eggs: capacity 12, size 7. The next egg goes in cup number 7 (counting from 0).

STEP 2Expanding the heap

Definition
  • An array cannot grow. To expand a heap we create a new array, twice as long.
  • We copy every value to the same index in the new array.
  • The tree shape depends only on the indexes, so the heap is still a heap. Nothing has to be re-arranged.
Picture it 🥚
  • The carton is full, so we buy a carton twice as big (the new array).
  • Each egg moves to the cup with the same number as before.
  • The extra cups at the end are the new free space.
OUTPUT
Inserted 30: size 1, capacity 2
Inserted 50: size 2, capacity 2
Inserted 40: size 3, capacity 4
Inserted 90: size 4, capacity 4
Inserted 70: size 5, capacity 8
90 70 40 30 50
Compare with hash tables
  • A hash table must rehash every key when it grows, because the index depends on the table size.
  • A heap just copies. Index 5 stays index 5.
Remember
  • Capacity = data.length. Size = values stored.
  • Full means size == data.length.
  • Expanding costs O(n), but doubling makes it rare.
End of Part I ✅

HeapSort

Goal: use a heap to sort an array.

Definition
  • HeapSort = a sorting method that uses a heap.
  • The idea: a heap always gives us the biggest value that is left.
  • Remove the biggest, then the next biggest, then the next… and the values come out in order.
Picture it 🃏
  • Imagine sorting a hand of cards. The cards are the values.
  • Pull out the highest card and lay it at the far right of the table.
  • Pull out the highest of what is left and lay it just to the left. Repeat until your hand is empty.
  • The heap is the helper that finds the highest card instantly each time.

VERSION 1The simple way: insert everything, remove everything

OUTPUT
30 40 50 60 70 80 90
It works, but… 💾
  • Version 1 needs a second array (inside the Heap object), as big as the first.
  • Version 2 sorts inside the original array. No extra memory.

VERSION 2The real HeapSort: two phases, one array

Phase 1 · Heapify
  • Heapify = turn any array into a heap, in place.
  • Start at the last node that has a child: index n / 2 - 1.
  • Trickle it down. Then do the node before it, and so on, back to the root.
Phase 2 · Sort
  • Swap the root (the biggest) with the last cell of the heap.
  • That cell is now finished. The heap shrinks by one.
  • Trickle down the new root. Repeat until the heap has one value.

Remember
  • Phase 1: make the array a heap. Phase 2: swap the root to the end, shrink, trickle down.
  • The array is split in two: the heap part at the front, the sorted part at the back.
  • A max-heap gives an array sorted from smallest to biggest, because the biggest values are placed at the end first.

HeapSort efficiency

Goal: understand why HeapSort is so much faster than the simple sorts.

Where the speed comes from
  • One trickle down costs at most the height of the tree: about log₂ n steps.
  • HeapSort does about n trickle downs.
  • n × log n → HeapSort is O(n log n).
Picture it 🏆
  • Imagine finding the best of 1,000 tennis players.
  • Selection sort is like checking every player one by one: about 1,000 looks per winner.
  • A heap is like a tournament bracket. A player only climbs about 10 rounds (the levels of the tree) to reach the top.
n (items)n² (bubble, selection, insertion)n × log₂ n (HeapSort)
10100about 33
10010,000about 664

Read the output
  • Each time n doubles, selection sort does about 4 times the work. That is n².
  • HeapSort does only a little more than 2 times the work. That is n log n.
OperationCostWhy
Heap insertO(log n)Trickle up: one swap per level at most
Heap removeO(log n)Trickle down: one swap per level at most
Peek at the biggestO(1)It is always in index 0

HeapSort strengths 💪
  • Always O(n log n). Sorted, reversed or random input: no bad case.
  • Sorts in place. No second array.
HeapSort weaknesses
  • Equal values may come out in a different order than they went in.
  • It jumps around the array a lot, so in practice some other O(n log n) sorts run a bit faster.
