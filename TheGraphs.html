Why do we need graphs?

Goal: see what kind of problem a graph describes, before we learn any new words.

The problem
  • Arrays, lists, trees and hash tables are for storing data and finding it again.
  • A graph is for describing how things are connected.
  • Things + connections between them = a graph.
Real-world situationThe things (vertices)The connections (edges)

Graph or tree?
  • A tree is a graph with extra rules: one root, and only one way to reach each node.
  • A graph has no root and no levels. Any vertex can connect to any other.
  • A graph can have cycles: you can walk around and come back to where you started.
Picture it 🚇
  • Imagine a subway map. Each station is a vertex. Each track between two stations is an edge.
  • The map does not care where the stations really are. It only shows what connects to what.

Storing a graph in Java

Goal: turn the picture into something a program can use.

Definition
  • Give every vertex a number: A = 0, B = 1, C = 2…
  • An adjacency matrix is a 2D array with one row and one column per vertex.
  • adj[a][b] = 1 means there is an edge between a and b. 0 means there is none.
  • An ordinary edge works both ways, so we set two cells: adj[a][b] and adj[b][a].
Picture it 🚌
  • Imagine a table of bus connections. The row is the city you leave, the column is the city you want to reach.
  • A 1 in the cell means "there is a direct bus". A 0 means "no direct bus".

Searches: depth-first search (DFS)

Goal: visit every vertex we can reach, by going as far as possible before turning back.

Definitions
  • A search (or traversal) visits every vertex that can be reached from a starting vertex, once each.
  • Depth-first search = go to an unvisited neighbor, then to one of its unvisited neighbors, and so on, as deep as possible.
  • Stuck (no unvisited neighbor)? Go back one step and try another way.
  • We mark each vertex as visited so a cycle cannot send us round and round forever.
Picture it 🧵
  • Imagine exploring a maze with a ball of string. Each junction is a vertex, each corridor is an edge.
  • You always take a corridor you have not tried yet, and you chalk an X at every junction (the visited mark).
  • At a dead end you follow your string back to the last junction with an untried corridor.

Where is the "string"? 🧵
  • Our dfs calls itself. Java remembers the way back for us on its call stack.
  • DFS can also be written with a loop and your own stack: push a vertex when you arrive, pop when you are stuck. Same idea, same order.
Remember
  • DFS = deep first, then back up.
  • It needs a visited array and a stack (ours is hidden in the recursion).
  • With a matrix it costs O(V²): for each vertex we scan one row.

Searches: breadth-first search (BFS)

Goal: visit the vertices closest to the start first, then the next ring, then the next.

Definition
  • Breadth-first search = visit all the neighbors of the start, then all of their neighbors, and so on.
  • It works outward in layers: 1 edge away, then 2 edges away, then 3.
  • It uses a queue: a newly found vertex waits at the back until its turn comes.
Picture it 🌊
  • Imagine dropping a stone in a pond. The splash is the start vertex.
  • The first ring of the ripple is every vertex 1 edge away. The second ring is 2 edges away.
  • The ripple reaches everything at the same distance at the same time. That is breadth-first.

Directed graphs and topological sorting

Goal: handle one-way connections, and put tasks in an order that respects "this before that".

Definition
  • In a directed graph every edge has a direction. It is drawn as an arrow.
  • The arrow A → B can be followed from A to B, but not back.
  • In the matrix we set one cell only: adj[a][b] = 1.
Picture it 🚗
  • Imagine a city with one-way streets. Each corner is a vertex, each street is an edge.
  • You may drive from A to B. Driving back from B to A needs a different street, if there is one.

STEP 1A one-way edge

OUTPUT

B to A? false

Topological sorting

Definition
  • A topological sort puts the vertices of a directed graph in a line so that every arrow points forward.
  • If there is an arrow A → B, then A comes before B in the line.
  • It only works when the graph has no cycles.
Picture it 🎓
  • Imagine planning your degree. Each course is a vertex.
  • Each arrow is a prerequisite: Java 1 → Java 2 means "Java 1 first".
  • A topological sort is a legal order to take the courses.
How it works
  • Count the incoming arrows of every vertex.
  • Pick a vertex with 0 incoming arrows: nothing has to come before it. Output it.
  • Remove its outgoing arrows: the vertices it pointed to wait for one thing less.
  • Repeat until every vertex is output.

Weighted graphs and the minimum spanning tree

Goal: put a number on every edge, then connect everything as cheaply as possible.

Definition
  • In a weighted graph every edge has a number, its weight: a distance, a cost or a time.
  • In the matrix we store the weight instead of 1. 0 still means "no edge".

The minimum spanning tree (MST)

Definitions
  • A spanning tree is a set of edges that connects all the vertices and has no cycle.
  • It always has exactly V − 1 edges.
  • The minimum spanning tree is the spanning tree with the smallest total weight.
Picture it 🔌
  • Imagine wiring six houses to the power grid. Each house is a vertex.
  • Each possible cable is an edge, and its cost is the weight.
  • Every house must be connected, using the least cable money. No house needs two routes. The answer is the MST.
How it works (Prim's algorithm)
  • Start a tree with one vertex.
  • Look at every edge that goes from inside the tree to a vertex outside it.
  • Add the cheapest one. The tree grows by one vertex.
  • Repeat until every vertex is in the tree.

Remember
  • MST = connect everything, cheapest total, no cycles, V − 1 edges.
  • Always take the cheapest edge that leaves the tree. That simple greedy rule gives the best answer.
  • A faster version keeps the candidate edges in a priority queue (heap) instead of scanning the matrix each round.

The shortest-path problem

Goal: find the cheapest route from one vertex to every other vertex.

Definitions
  • The length of a path in a weighted graph is the sum of its edge weights.
  • The shortest path from A to X is the path with the smallest sum.
  • It is not always the path with the fewest edges. A detour over cheap edges can win.
  • Dijkstra's algorithm finds the shortest path from one start vertex to all the others.
Picture it 🗺️
  • Imagine a GPS. Each intersection is a vertex, each road is an edge, the minutes to drive it are the weight.
  • The GPS keeps a notepad: the best time found so far to every place.
  • Whenever it discovers a quicker way, it crosses out the old time and writes the better one.

STEP 1The key idea: is the detour cheaper?

OUTPUT
Best distance to B: 3
How Dijkstra's algorithm works
  • Write distance 0 for the start and ∞ (no route yet) for everything else.
  • Pick the closest vertex that is not finished. Its distance is now final.
  • For each of its neighbors, ask the Step 1 question: is going through this vertex cheaper? If yes, update.
  • Repeat until every vertex is finished.

MST ≠ shortest paths ⚠️
  • The MST used E – F (5) to reach F. Total cable: 15.
  • The shortest path to F uses D – F (6): A, C, B, D, F = 14.
  • Different questions, different edges.
Remember
  • Always finish the closest unfinished vertex next.
  • The weights must not be negative.
  • Our version costs O(V²). With a heap it is faster on big graphs.

The Knight's Tour

Goal: solve a famous puzzle by treating a chessboard as a graph.

Definitions
  • A chess knight moves in an L shape: 2 squares one way, then 1 square sideways. Up to 8 possible moves.
  • The Knight's Tour: move the knight so that it lands on every square exactly once.
  • As a graph: each square is a vertex. Two squares are joined by an edge when a knight can jump between them.
  • So the puzzle asks for a path that visits every vertex once.
New word: backtracking
  • Backtracking = try a choice. If it leads to a dead end, undo it and try the next choice.
  • It is depth-first search with one extra step: when we go back, we un-mark the square, so another route may use it.
Picture it 🧩
  • Imagine solving a maze in pencil. Each square you enter gets a pencil number (the move number).
  • At a dead end you erase your last number and step back.
  • Then you try the next direction from there. Erasing is the backtracking.

Read the output
  • Each number is the move on which the knight landed on that square. Follow 1, 2, 3… to 25.
  • The program tried and erased many wrong routes before it found this one.
Watch out: it gets slow fast 🐢
  • A 5 × 5 board is solved in a blink.
  • A full 8 × 8 board has so many possible routes that this simple version can run for a very long time.
  • Backtracking tries choices one by one. When the number of choices explodes, so does the time.
