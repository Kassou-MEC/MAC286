    03
    Where local variables live conceptually

    Stack memory: the method's working area

    Before we talk about arrays, students need a picture of where ordinary local variables are kept during a method call.

    Instructor narrative

    “When a method runs, Java needs a temporary working area for that method. In our classroom memory model, we call that the stack.”

    “The stack is where we will picture local variables such as int x and local reference variables such as int[] scores.”

    public static void main(String[] args) {
    int x = 10;
    int y = 20;
}

    For this lesson, picture x and y inside the current method's stack frame.

    Key distinction

    Primitive local variables hold primitive values directly. Reference variables hold references to objects.

    Stack conceptual stack frame

    main()
    x10
    y20
    Ask students

    If x is a primitive int, what does the variable itself hold?

    04
    Where objects live conceptually

    Heap memory: where array objects are created

    Now compare a primitive value with an array object.

    int x = 10;
int[] scores = new int[4];
    Instructor narrative

    “The variable x can hold its integer directly. But the array is an object. In the usual introductory Java memory model, objects are created in the heap.”

    Important classroom note

    The stack/heap picture is a useful conceptual model for introductory Java. Real JVM implementations may manage memory internally in more complex ways, but this model correctly explains references, object lifetimes, aliasing, and array behavior for students.

    07
    Two variables, one heap object

    Aliasing: two references can point to the same array

    int[] a = {10, 20, 30};
int[] b = a;
    Prediction

    After b[0] = 99;, what does a[0] become?

    Instructor explanation

    “Assignment between reference variables copies the reference, not the array object itself. So both variables can reach the same heap object.”

    A reference to nowhere

    Understanding null

    int[] data = null;
    Ask students

    What happens if Java tries to evaluate data.length?

    Important precision

    A local variable declared only as int[] data; must be definitely assigned before use. To demonstrate null, explicitly write int[] data = null;.

    09
    What if no reference remains?

    Garbage collection: unreachable objects can be reclaimed

    Start with:

    int[] data = {5, 10, 15};
    Now execute 
    data = null;
    Instructor narrative

    “The array object does not instantly disappear the moment the reference is removed. But if no reachable reference can get to that object anymore, the JVM may later reclaim that memory through garbage collection.”

    Key phrase for students

    Unreachable object = an object that the running program can no longer reach through any live reference.

    10
    Put the whole memory story together

    The complete mental model

    Closing narrative

    “When you see an array, separate the picture into two parts: the reference variable and the array object. Then draw the arrow between them.”

    Stack side

    • Current method calls
    • Local primitive variables
    • Local reference variables
    • Temporary working data for method execution

    Heap side

    • Array objects
    • Objects created with new
    • Objects may be shared by several references
    • Unreachable objects may later be garbage-collected
    Final memory trace 
    int[] first = {4, 8, 12};
int[] second = first;
second[1] = 50;

    Ask students to draw:

    1. Two reference variables in the stack frame.
    2. One array object in the heap.
    3. Two arrows pointing to the same array.
    4. The array contents [4, 50, 12].
