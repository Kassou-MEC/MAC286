Stacks, Queues & Priority Queues

Three ways to line things up and decide who gets served next. Hover (or tap) any line of code to see what it does. Play with the live demos. 🚀

🧭 Why 📚 Stack 🎢 Queue 🚑 Priority Queue ⚖️ Compare 🧠 Quiz

🧭 Why do we need these?

  • Problem
    An array lets you grab any element (a[5]). Sometimes that freedom is a bug: you want a strict rule for what comes out next.
  • Idea
    A restricted collection: you can only add/remove at specific ends. Fewer operations → simpler, safer, faster code.
  • Three rules
    Stack → last one in is the first one out.   Queue → first one in is the first one out.   Priority Queue → the most important one is out first.
Picture it: 📚 a pile of plates (Stack) · 🎢 a line at a theme park (Queue) · 🚑 an emergency room (Priority Queue). Here the plate / person / patient is the element, and the rule for who leaves next is the data structure.

🗺️ The big picture

📚 Part 1

Stack — Last In, First Out (LIFO)

📖 Definitions (one word at a time)

  • Stack
    A collection where you add and remove only at one end, called the top.
    Deque<Integer> s = new ArrayDeque<>();
  • push
    Put a new element on the top.
    s.push(7);
  • pop
    Remove the top element and give it back.
    int x = s.pop(); // 7
  • peek
    Look at the top without removing it.
    int t = s.peek();
  • isEmpty
    Ask "is there anything in there?" — check before you pop!
    if (!s.isEmpty()) s.pop();
  • LIFO
    Last In, First Out — the last thing pushed is the first thing popped.
Picture it: a stack of plates 🍽️. You put a clean plate on top (push), you take a plate from the top (pop). Nobody pulls a plate from the middle — that's how you break dishes. The plate = element, the pile = stack, the top plate = top.

🎢 Part 2

Queue — First In, First Out (FIFO)

📖 Definitions (one word at a time)

  • Queue
    A collection with two ends: elements enter at the rear and leave from the front.
    Queue<String> q = new ArrayDeque<>();
  • offer
    Add to the rear (also called enqueue).
    q.offer("Ana");
  • poll
    Remove from the front and give it back (also called dequeue). Returns null if empty.
    String next = q.poll();
  • peek
    Look at the front without removing.
    String who = q.peek();
  • FIFO
    First In, First Out — fair: whoever came first is served first.
  • Deque
    "Double-ended queue" — can add/remove at both ends. ArrayDeque is a Deque, so it can act as a stack or a queue.
Picture it: the line at the DMV 🏢. You join at the back (offer). The clerk calls the person at the front (poll). Cutting the line = not allowed. Person = element, the line = queue, the clerk's window = front.

🚑 Part 3

Priority Queue — the most important goes first

📖 Definitions (one word at a time)

  • Priority Queue
    A queue where poll() gives you the element with the highest priority, not the oldest.
    PriorityQueue<Integer> pq = new PriorityQueue<>();
  • priority
    A rule for comparing two elements. Java's default: smaller = more important (a min-priority queue).
  • offer
    Insert; the structure quietly reorganizes itself.
    pq.offer(42);
  • poll
    Remove and return the smallest (by default).
    int best = pq.poll();
  • Comparator
    An object that tells Java how to compare — this is how you make "largest first", or "shortest name first".
    new PriorityQueue<>(Comparator.reverseOrder())
  • heap
    The data structure inside a PriorityQueue: a tree stored in an array where every parent is ≤ its children. That's why the smallest is always at the top (index 0).
Picture it: an emergency room 🏥. Patients arrive in some order, but the doctor sees the most critical one first, no matter who came first. Patient = element, severity score = priority, the triage board = heap.

🖼️ The heap: a tree hiding in an array

🧮 Magic formulas (no pointers needed!):
children of index i → 2i+1 and 2i+2
parent of index i → (i-1)/2
Rule: parent ≤ children everywhere → smallest sits at index 0.
